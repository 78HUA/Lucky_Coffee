## 关键约定（实现时必须严格一致）

1. **所有请求都要带 `appkey`**,GET 放 query,POST 放 body。
2. **POST 参数格式是 `application/x-www-form-urlencoded`**（`a=1&b=2`），**不是 JSON**。
   → Spring Boot 用 `@RequestParam` / `@ModelAttribute`，**不要用 `@RequestBody`**。
3. **响应统一为 JSON，用自定义 `code` 判断成功**，不是 HTTP 状态码。
4. **登录态通过 `tokenString` 参数传递**，不是 `Authorization` 头。

### 已观测到的 code 值

| 接口 | code | msg |
|---|---|---|
| `/register` | 100 | 注册成功（见 `Api.ets` 注释） |
| `/login` | 200 | 登录成功，返回 `token`（见 `Api.ets` 注释） |
| `/typeProducts` | 500 | — |
| `/search` | `"Q001"` | 搜索商品成功 **← 注意是字符串，不是数字** |
| `/productDetail` | 600 | 查询商品详情成功 |

> ⚠️ `code` 的类型在不同接口间不一致（数字 / 字符串），后端复刻时必须逐一核对。

### 字段命名陷阱

**列表接口和详情接口的字段命名不同**,必须分别处理:

| 语义 | 列表接口(`/typeProducts`) | 详情接口(`/productDetail`) |
|---|---|---|
| 小图 | `smallImg` | `small_img` |
| 大图 | `largeImg` | `large_img` |
| 热门 | `isHot` | `is_hot` |
| 分类名 | `typeDesc` | `type_desc` |

详情接口还**额外返回 4 个客制化维度**(列表接口没有):
`tem`/`tem_desc`(温度)、`milk`/`milk_desc`(奶)、`sugar`/`sugar_desc`(糖)、`cream`/`cream_desc`(奶油)。
